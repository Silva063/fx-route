# fx-route — самый выгодный маршрут обмена валют (ПМР ↔ Молдова)

Сборщик курсов банков обоих берегов Днестра и PWA для телефона, которая считает,
как выгоднее обменять одну валюту на другую: напрямую или через USD/EUR, с учётом каналов
(наличные, карта, онлайн) и комиссий. Расчёт маршрутов — одна реализация (`src/core`)
для сборщика и браузера.

- Курсы никогда не подставляются и не придумываются: нет данных — «нет данных».
- У каждого курса есть время получения и, если источник его публикует, время действия.
- Защита сайтов от ботов не обходится: такой источник помечается «только вручную».

Разведка источников — [docs/recon.md](docs/recon.md). Правила проекта — [CLAUDE.md](CLAUDE.md).

## Установка и запуск на ПК

Нужен Node.js 22 или новее.

```sh
npm install
npm test                 # тесты на сохранённых копиях страниц, без сети
npm run collect          # сбор всех источников в data/rates.json
npm run collect -- --only maib,victoriabank
```

Сбор вежливый: одна страница на хост раз в 3 секунды (или реже, если так просит robots.txt),
поэтому полный проход занимает несколько минут — в основном из-за ~58 отделений FinComBank.

Каждый запуск объединяется с существующим `data/rates.json`: для каждого предложения
(банк + отделение + канал + направление) остаётся самая свежая запись. Результаты с разных
машин объединяются так же:

```sh
npm run merge -- data/rates.json other/rates.json --out data/rates.json
```

### Поиск маршрута из терминала

```sh
npm run route -- 10000 RUP MDL                       # наличные → наличные, топ-5
npm run route -- 10000 MDL RUP --accounts maib       # у меня есть карта maib
npm run route -- 500 USD MDL --from-channel card --from-account maib --to-channels card,cash
npm run route -- 10000 RUP MDL --branches mine --my-branches "fincombank|11041234"
npm run route -- 10000 RUP MDL --at 2026-09-29T09:00  # по курсам, действующим в этот момент
```

- По умолчанию — курсы, действующие сейчас. Курсы «с завтрашнего дня» показываются отдельно.
- Карты и онлайн-банки участвуют только из списка `--accounts` («мои счета»).
- Наличные: по умолчанию выдаются целые единицы, остаток возвращается в исходной валюте
  (правило `routing.cashRounding` в `config/settings.json`, помечено «не проверено»).
- Одинаковые по итогу варианты через разные банки объединяются в один маршрут
  («тот же итог: …»). При равном итоге выше маршрут с большим остатком в исходной валюте.
- Пометки у шагов: «канал не подтверждён», «правило комиссии не проверено»,
  «правило округления наличных не проверено», «курс устарел», «курс введён вручную».

## Приложение (PWA)

```sh
npm run dev       # локально: http://localhost:5173
npm run build     # сборка в dist/ (берёт data/rates.json и config/)
npm run preview   # проверить сборку: http://localhost:4173
```

- **Маршрут** — сумма, откуда/куда, канал, дата (только сегодня и будущее), топ маршрутов
  с шагами, курсом, комиссиями, сдачей, возрастом курса и пометками. Вверху — когда собраны курсы.
- **Источники** — статус каждого банка и последний успешный сбор; официальные курсы справочно;
  для «только вручную» (Energbank, сработавшая защита) — ссылка на сайт и быстрый ввод курса.
- **Мои курсы** — свои пункты обмена и курсы (IndexedDB на устройстве), экспорт/импорт JSON.
- **Настройки** — «мои счета» (где есть карта/онлайн-банк), каналы, «мои отделения»
  с поиском и фильтром по городу, исключение устаревших курсов, список непроверенных правил.
- Работает офлайн: приложение и последний `rates.json` сохраняются service worker'ом,
  возраст данных всегда виден.

## Деплой на GitHub Pages

Код лежит в основной ветке, курсы — в отдельной ветке `data` (только `rates.json`).
Приложение читает курсы **во время работы** из
`https://raw.githubusercontent.com/<вы>/<репозиторий>/data/rates.json`, поэтому:

- сайт пересобирается только при изменении кода, а не при каждом обновлении курсов;
- публикация курсов никогда не конфликтует с кодом;
- новые курсы видны в приложении не позже чем через ~5 минут после публикации
  (столько CDN raw.githubusercontent.com кеширует файл).

**Репозиторий должен быть публичным.** GitHub Pages из приватного репозитория доступен только
на платных тарифах, а raw.githubusercontent.com отдаёт файлы приватного репозитория только
с токеном, которого у приложения нет. В репозитории нет секретов: только код, конфиги и курсы
с публичных сайтов банков. Ручные курсы и настройки хранятся на телефоне и в репозиторий не попадают.

### Один раз

1. Создайте **публичный** репозиторий на GitHub и запушьте проект:
   ```sh
   git init -b main
   git add .
   git commit -m "fx-route"
   git remote add origin https://github.com/<вы>/<репозиторий>.git
   git push -u origin main
   ```
   При первом `git push` Git Credential Manager откроет окно входа в GitHub и сохранит доступ
   (см. «По расписанию в Windows»).
2. Settings → Pages → Source: **GitHub Actions**.
3. Settings → Actions → General → Workflow permissions: **Read and write**
   (нужно `collect.yml`, чтобы пушить в ветку `data`).
4. Опубликуйте первые курсы: `npm run update` — ветка `data` создастся сама.
5. Actions → Pages → Run workflow (или любой push в основную ветку) — первая сборка сайта.

Сайт: `https://<вы>.github.io/<репозиторий>/`. На телефоне — «Добавить на главный экран».
Проверить, что курсы опубликованы: `git ls-remote origin data`.

### Как обновляются данные

- **ПК (основной сборщик):** `npm run update` = сбор + `npm run publish-data`.
  Публикация берёт уже опубликованные курсы, объединяет с локальными (для каждого курса —
  самый свежий, будущие курсы не затирают действующие) и пушит в ветку `data`.
- **GitHub Actions (дополнительно):** `.github/workflows/collect.yml` — сбор 3 раза в день
  (или вручную: Actions → Collect → Run workflow), та же публикация. Push со стандартным
  `GITHUB_TOKEN` других workflow не запускает — и не нужно, пересборка сайта для курсов не требуется.
- **Код:** push в основную ветку → `.github/workflows/pages.yml`: тесты, сборка, деплой.

### Офлайн

Service worker хранит оболочку приложения (HTML, JS, CSS, иконки) и отдаёт её **сначала из кеша**.
`rates.json` и `config.json` — **сначала сеть, при неудаче кеш** (ожидание сети до 6 секунд).
Без сети приложение работает на последней сохранённой копии курсов и показывает её возраст.

### По расписанию в Windows

Планировщик заданий → «Создать задачу»:

- **Общие:** «Выполнять только для пользователей, вошедших в систему» — от своей учётной записи.
- **Триггеры:** ежедневно, повторять каждые 4–6 часов.
- **Действия:** программа `cmd.exe`, аргументы:
  `/c cd /d "D:\Банки\Claude Code" && npm run update >> collect.log 2>&1`

**Как `git push` получает учётные данные.** На ПК установлен Git Credential Manager
(`git config --get credential.helper` → `manager`). После первого ручного `git push` он хранит
токен GitHub в Диспетчере учётных данных Windows **вашего пользователя**. Задача, запущенная
от вашей учётной записи, берёт его оттуда без вопросов. Поэтому:

- запускайте задачу от своего пользователя. Вариант «Выполнять для всех пользователей» тоже
  работает, но только с сохранённым паролем; с галочкой «Не сохранять пароль» у задачи нет доступа
  к Диспетчеру учётных данных, и push упадёт;
- если GitHub отзовёт или сменит токен, GCM захочет открыть окно входа — в фоне это невозможно,
  push завершится ошибкой (видно в `collect.log`). Лечится одним ручным `git push` или `npm run update`;
- альтернатива, не зависящая от входа через браузер, — fine-grained Personal Access Token
  с правом Contents: Read and write только на этот репозиторий: при ручном `git push` в окне GCM
  выберите вход по токену («Token») и вставьте его — GCM сохранит токен так же.

Сбор курсов работает и без push: если публикация не удалась, `data/rates.json` на ПК всё равно
обновлён, следующий успешный `npm run update` опубликует накопленное. Не запускайте чаще
нескольких раз в день: банки обновляют курсы 1–3 раза в сутки.

## Как добавить банк

Ядро не меняется: источник — это запись в конфиге и, при необходимости, адаптер.

### 1. Разведка

Найдите страницу курсов и посмотрите, что она отдаёт на обычный запрос:

```sh
node recon/probe.mjs    # шаблон проверки доступности; добавьте свою цель в список targets
```

Проверьте `robots.txt`. Если нужная страница запрещена или сайт показывает проверку браузера/капчу —
автосбор не делается, переходите к шагу 2 с `manual-only`.

### 2. Запись в `config/sources.json`

```json
{
  "id": "newbank",
  "name": "Новый банк",
  "jurisdiction": "MD",
  "kind": "bank",
  "website": "https://newbank.md/",
  "ratesUrl": "https://newbank.md/curs",
  "collect": "auto",
  "adapter": "html-tables",
  "tables": {
    "cash": { "label": "Numerar", "channel": "cash", "use": "offer" },
    "card": { "label": "Carduri", "channel": "card", "use": "offer" }
  }
}
```

- `tables` — **белый список**. Котировки из таблиц вне списка отбрасываются. Не добавляйте
  курсы для комиссий, кредитов, пенсий и т.п. — это не предложения обмена.
- `channel`: `cash`, `card`, `online` или `unknown`. Если сайт не подписывает канал, а вы его
  предполагаете, укажите `"channelConfidence": "assumed"` — курс пойдёт в маршрут с пометкой
  «канал не подтверждён». `unknown` — только справочно, в маршрут не идёт.
- Автосбор невозможен: `"collect": "manual-only"` и `"manualReason": "почему"`, без `adapter`.

### 3a. Простой сайт — без кода (`html-tables`)

Если курсы лежат в HTML-таблице, опишите её в `params`:

```json
"params": {
  "url": "https://newbank.md/curs",
  "quote": "MDL",
  "date": { "selector": ".rates-date" },
  "tables": [
    {
      "table": "cash",
      "locate": { "heading": "^Numerar$" },
      "columns": { "code": 0, "buy": 1, "sell": 2 }
    },
    {
      "table": "card",
      "locate": { "selector": "#card-rates table" },
      "expect": "card",
      "columns": { "code": 0, "buy": 1, "sell": 2 }
    }
  ]
}
```

Способы найти таблицу (`locate`):

- `{ "selector": "CSS" }` — CSS-селектор таблицы;
- `{ "heading": "регулярка" }` — таблица, перед которой стоит заголовок с таким текстом;
- `{ "tab": { "scope", "titles", "panels", "title" } }` — вкладки: заголовки и панели
  сопоставляются по порядку, нужная панель ищется по регулярке `title`.

`expect` — регулярка, которой должен соответствовать текст вокруг таблицы (или предка
`container`). Защищает от того, что после смены вёрстки селектор попадёт в чужую таблицу.
`columns.nominal` — столбец номинала, если цены указаны за 10/100 единиц.
Примеры: maib, OTP, ProCredit, Eximbank МД, Эксимбанк ПМР в `config/sources.json`.

### 3b. Сложный сайт — модуль

JSON-API, курсы по отделениям, нетабличная вёрстка — пишется адаптер
(`src/collector/adapter.ts`, тип `Adapter`) и регистрируется в `src/collector/adapters/index.ts`.
Адаптер только читает страницы через `ctx.http` и возвращает котировки как опубликовано;
белый список, проверки правдоподобности и превращение в предложения делает ядро.
Для чисел используйте `parseRate` — он возвращает `null` вместо «-», «0.0000» и мусора.
Примеры — `src/collector/adapters/moldova.ts`, `pmr.ts`.

### 4. Фикстура и тест

```sh
npm run capture -- --only newbank   # сохранит ответы сайта в test/fixtures/sources/newbank
```

Добавьте в `test/collector/adapters.test.ts` проверку нескольких значений, сверенных с сайтом
глазами. Общие тесты сами проверят, что есть все таблицы белого списка, нет предупреждений
и курсы проходят проверки правдоподобности. Когда сайт поменяет вёрстку, `npm run capture`
и `npm test` покажут, где именно сломалось.

### 5. Проверка

```sh
npm test && npm run typecheck
npm run collect -- --only newbank
```

В итоге у источника должен быть статус `ok`. `partial` — часть таблиц не найдена (см. сообщение),
`protected` — сработала защита от ботов, `robots-blocked` — запрещено robots.txt.
