Playwright (JS-рендеринг) **ни для одного источника не обязателен**. Все JS-сайты берут данные из JSON-эндпоинтов, которые отвечают на обычный запрос.

**Apps Script в целом.** `UrlFetchApp` не исполняет JS и ходит с IP Google, добавляя к User-Agent свою метку. Поэтому он применим только к открытым JSON/XML (Агропромбанк, Сбербанк ПМР, Victoriabank, BNM) и к простому HTML без защиты. Для источников с Incapsula/FOXCLOUD/Cloudflare он не подходит. Всё это — оценка, запуском не проверено.

## 3. Что важно для модели данных и маршрутов

- **Сбор 0,1% в Молдове.** При покупке физлицом иностранной валюты за наличные взимается обязательный сбор 0,1% (закон № 827-XIV от 18.02.2000). Это прямо написано у MICB, Victoriabank, FinComBank и EuroCreditBank. Его нужно заложить в конфиг комиссий, а не угадывать для каждого банка.
- **Кроссы в ПМР идут через рубль ПМР.** Агропромбанк пишет, что конвертация одной иностранной валюты в другую определяется курсами этих валют к рублю ПМР. Прямые пары USD/MDL есть только в APB Online.
- **Не все таблицы — предложения обмена.** У Агропромбанка есть таблицы «для списания комиссий» и «курс потребительских кредитов», у Сбербанка ПМР — «спецкурс для пенсий РФ». Их в маршрут брать нельзя.
- **Курсы по отделениям** есть у FinComBank (проверено, различаются), EuroCreditBank и Victoriabank («Sucursala nr.3»). Это поле `branch` модели.
- **Несколько курсов в день** публикует Victoriabank. Время курса нужно брать из данных источника, если оно там есть, иначе — время получения.
- **Официальный курс ПРБ** публикуется заранее, на следующий день. Дата действия курса не совпадает с датой получения.

## 4. Решения, которые нужны от тебя

1. **Выборочная защита (Эксимбанк ПМР, Eximbank МД).** Сейчас страница с курсами отдаётся на обычный `fetch` без решения каких-либо проверок. Предлагаю собирать обычным `fetch`, а при получении challenge-страницы автоматически ставить статус «защита — только вручную» без попыток обхода. Альтернатива — сразу пометить оба банка «только вручную».
2. **Energbank и robots.txt.** Варианты: (а) «только вручную»; (б) рендерить публичную страницу через Playwright, браузер сам обращается к `/api/`; (в) обращаться к JSON напрямую, не чаще нескольких раз в день. Рекомендую (а) или (б).
3. **Курсы по отделениям** (FinComBank, EuroCreditBank): собирать все отделения или только основной курс?
4. **Агрегаторы** (curs.md, valutar.md, i-pmr.com, kurspmr.com) не исследовались. Они могут быть резервом для защищённых банков, но это не первоисточник. Нужны ли они?

## 5. Как проверить GitHub Actions

Workflow уже лежит в [.github/workflows/recon-probe.yml](../.github/workflows/recon-probe.yml) и запускает тот же [recon/probe.mjs](../recon/probe.mjs).

1. Создай репозиторий на GitHub (можно приватный) и запушь в него эту папку.
2. Открой Actions → «Recon probe» → «Run workflow».
3. Пришли лог шага `node recon/probe.mjs` или артефакт `probe-result-gha`. После этого колонка «GitHub Actions» будет заполнена.

Либо установи `gh` (`winget install GitHub.cli`) и выполни `gh auth login`. Тогда репозиторий можно будет создать и проверку запустить отсюда.
