# fx-route — правила проекта

Сервис поиска самого выгодного маршрута обмена валют: рубль ПМР ↔ молдавский лей,
напрямую или через USD/EUR, через банки обоих берегов. Интерфейс на русском.

## Жёсткие правила

- **Никогда не подставлять и не придумывать курсы.** Нет числа — нет котировки (`parseRate` → null).
  `-`, `–`, пусто, `0` означают «нет данных». В интерфейсе — «нет данных».
- **Всегда хранить и показывать время получения** (`fetchedAt`) и, если источник его даёт, время действия (`validFrom`).
- **Защиту от ботов не обходить.** Никакой маскировки: честный User-Agent из `config/settings.json`,
  без подмены отпечатков, без stealth-плагинов, без решения капч и challenge.
  Challenge распознаётся (`src/collector/challenge.ts`) → статус `protected` («только вручную»).
- **Соблюдать robots.txt**, включая `Crawl-delay`. Пауза между запросами к хосту — не меньше `http.minDelayMs`.
  Никаких частых опросов.
- **Переходы между каналами** (снятие, пополнение, переводы) и их комиссии — только из `config/transitions.json`,
  заполняемого человеком. Не выдумывать.
- Официальные курсы (BNM, ПРБ) — только справочный ориентир и эталон для проверок, не предложение обмена.
- Приднестровский Сбербанк (prisbank.com) — банк ПМР, не российский Сбербанк.
  Эксимбанк ПМР (bankexim.com) и Eximbank Молдовы (eximbank.md) — разные банки.

## Модель данных (src/core — изоморфно, без node:*)

- Рубль ПМР — код `RUP` (так его обозначают сами банки ПМР).
- Адаптер возвращает `RawQuote` как опубликовано (банк покупает/продаёт base за quote, номинал).
  Ядро превращает котировку в два направленных `Offer` (`rate` = сколько `to` за 1 `from`).
- **Белый список таблиц:** `tables` источника в `config/sources.json`. Котировки из других таблиц отбрасываются.
  Курсы для комиссий, кредитов, пенсий, таможенных агентств maib, marketType=13 Victoriabank — не обмен.
- Канал `unknown` (сайт не подписал таблицу) → статус `reference`: показывается, в маршрут не идёт,
  пока человек не подтвердит канал в конфиге.
- `channelConfidence: "assumed"` (например, «в отделениях» → наличные) — курс идёт в маршрут,
  но в интерфейсе помечается «канал не подтверждён». Меняет канал/уверенность только владелец.
- Проверки правдоподобности (`plausibility.ts`): buy < sell, спред, отклонение от официального курса.
  Пороги в `config/settings.json`, переопределения `"USD/RUB"`, `"UAH"`, `"PMR:USD/MDL"`.
  Не прошёл → `suspicious`: виден, в маршрут не идёт.
- Комиссии по юрисдикции — `config/fees.json` (например, сбор 0,1% при покупке наличной валюты за леи в МД).
  `verified: false` — осторожная оценка, применяется, но в интерфейсе помечается как непроверенная.
- Узел графа = (валюта, канал, счёт): для card/online счёт = банк, наличные взаимозаменяемы.
- Объединение запусков (`mergeRates`): версия = `source|branch|channel|from>to` + `validFrom`;
  хранятся действующая сейчас и все будущие версии (курс «с завтра» не затирает сегодняшний).
- Рубль ПМР — `RUP`, российский рубль — `RUB`; их нельзя смешивать (есть тест на фикстурах).
- Маршруты (`src/core/routes.ts`): полный перебор до `routing.maxExchanges` обменов, курсы на момент `at`,
  только «мои счета» для card/online и «мои отделения» при branchMode=mine. Округление наличных —
  `routing.cashRounding` (не проверено). Каждый шаг несёт пометки, их нельзя терять в интерфейсе.

## Структура

- `src/core/` — модель, проверки, объединение, комиссии (используется и сборщиком, и PWA).
- `src/collector/` — HTTP-клиент, robots, распознавание защиты, раннер, CLI, `adapters/`.
- `config/` — `sources.json` (реестр источников), `fees.json`, `transitions.json`, `settings.json`.
- `test/` — vitest; `test/fixtures/` — сохранённые копии страниц.
- `docs/recon.md` — разведка источников (этап 0).
- `web/` — PWA (Preact + Vite), импортирует `src/core` напрямую: одна реализация расчёта.
  `scripts/prepare-web-data.ts` кладёт config.json и rates.json в `web/public/data`.
- Данные публикуются в ветку `data` (`scripts/publish-data.ts`, git plumbing + force-with-lease);
  основная ветка — только код. Pages собирается только из кода; PWA читает rates.json во время работы
  из `raw.githubusercontent.com/<repo>/data/rates.json` (VITE_RATES_URL в pages.yml). Запрос — только
  «простой» fetch без своих заголовков: raw.githubusercontent.com отвечает 403 на CORS-preflight.
  Репозиторий должен быть публичным.

## Добавление источника

1. Запись в `config/sources.json`: id, юрисдикция, URL, `tables` (белый список с каналами), `adapter`.
   Если автосбор невозможен или запрещён — `collect: "manual-only"` и `manualReason`.
2. Простая HTML-таблица — декларативно: `"adapter": "html-tables"` + `params` (без кода).
   Иначе — модуль в `src/collector/adapters/` и регистрация в `adapters/index.ts`. Ядро не трогать.
3. `npm run capture -- --only <id>` — записать фикстуру; добавить в `test/collector/adapters.test.ts`
   значения, сверенные с сайтом глазами. Подробно — README, «Как добавить банк».

## Команды

- `npm test` — тесты; `npm run typecheck` — проверка типов.
- `npm run collect -- [--only id1,id2] [--out data/rates.json]` — сбор с объединением в существующий файл.
- `npm run merge -- a.json b.json --out data/rates.json` — объединить результаты разных запусков.
- `npm run capture [-- --only id]` — перезаписать фикстуры адаптеров с живых сайтов (вежливо, с паузами).
- `npm run route -- 10000 RUP MDL [--accounts maib] [--at ...]` — маршруты по data/rates.json.
- `npm run dev` / `npm run build` — PWA; `npm run update` — сбор + публикация в ветку data.
- `npm run typecheck` проверяет и Node-часть, и `web/` (ядро не должно импортировать node:*).

## Как работать

- Поэтапно: разведка → модель и ядро → адаптеры → маршруты → PWA → деплой. После этапа — короткий отчёт.
- Если что-то не проверено — так и писать: «не проверено».
